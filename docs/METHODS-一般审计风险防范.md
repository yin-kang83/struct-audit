# 第 45 章 一般审计如何防范风险

## 45.1 审计风险模型

```text
审计风险 = 重大错报风险 × 检查风险
重大错报风险 = 固有风险 × 控制风险
```

审计师能控制的，主要是**检查风险**：

```text
程序越有效、证据越充分，检查风险越低
```

但不能把检查风险降到零：

```text
审计是合理保证，不是绝对保证
```

## 45.2 六道防线

### 第一道：承接与独立性

```text
1 客户诚信
2 业务风险
3 独立性与利益冲突
4 专业胜任能力
5 收费安排
```

如果这一道失守，后面全白搭。

### 第二道：风险评估与计划

```text
1 了解被审计单位及其环境
2 了解内部控制
3 识别重大错报风险
4 确定重要性
5 设计应对程序
```

计划不是形式，是“把风险分配到程序”。

### 第三道：内部控制

```text
1 控制环境
2 风险评估过程
3 信息系统与沟通
4 控制活动
5 对控制的监督
```

审计不是替企业做内控，是：

```text
了解内控 → 判断是否依赖 → 决定控制测试/实质性程序
```

### 第四道：实质性程序

```text
1 检查
2 监盘
3 函证
4 访谈
5 重新计算
6 分析程序
```

核心：

```text
证据要相关、可靠、充分
```

### 第五道：复核与质量控制

```text
1 项目组内部复核
2 项目质量复核（EQCR）
3 专业技术支持
4 质量管理制度
5 工作底稿归档
```

复核不是“签字”，是：

```text
独立看一遍：结构、证据、结论、边界
```

### 第六道：报告与沟通

```text
1 与治理层沟通
2 未更正错报
3 关键审计事项
4 审计意见
5 管理建议书
```

报告是风险防范的最后一关：

```text
不能把“没查出来”写成“没问题”
```

## 45.3 具体手段

### 1 重要性

```text
财务报表整体重要性
实际执行重要性
明显微小错报临界值
```

作用：

```text
决定查多少、查多深、什么必须调整
```

### 2 分析程序

```text
本期 vs 上期
实际 vs 预算
行业 vs 公司
```

作用：

```text
找异常，不直接下结论
```

### 3 函证/监盘/访谈

```text
函证：外部证据
监盘：实物证据
访谈：了解流程/异常
```

作用：

```text
突破“内部资料自说自话”
```

### 4 抽样

```text
统计抽样/非统计抽样
分层/整群/随意
```

作用：

```text
在有限成本下，获得合理保证
```

### 5 舞弊风险

```text
收入确认舞弊推定
管理层凌驾控制
异常交易/关联方
```

作用：

```text
对高风险领域，不能只做常规程序
```

### 6 持续经营

```text
经营/财务/其他迹象
管理层评估
期后事项
```

作用：

```text
防止“报表编得平，公司撑不住”
```

### 7 IT 与数据

```text
系统一般控制
接口/权限/日志
数据完整性
```

作用：

```text
防止“数据源错了，后面全错”
```

### 8 职业道德与轮换

```text
独立性
客观性
保密
收费/礼品/关系
项目合伙人轮换
```

作用：

```text
防止“专业能力够，立场不够”
```

## 45.4 和结构审计的关系

```text
一般审计：防“程序失败”
  计划、内控、证据、复核、报告

结构审计：防“假设失败”
  结构、参数、残差、边界
```

两者不能互相替代：

```text
结构审计做得再好，
没有函证/监盘/复核，仍然可能失败。

一般审计做得再全，
结构假设错了，残差仍然可能为零。
```

## 45.5 风险防范清单

| 风险 | 防范手段 | 证据 |
|---|---|---|
| 承接风险 | 客户诚信/独立性 | 背景调查/声明 |
| 计划风险 | 风险评估/重要性 | 计划底稿 |
| 内控风险 | 了解/控制测试 | 穿行测试 |
| 证据风险 | 函证/监盘/重新计算 | 外部证据 |
| 抽样风险 | 分层/样本量 | 抽样表 |
| 舞弊风险 | 收入推定/凌驾测试 | 异常清单 |
| 持续经营 | 评估/期后事项 | 现金流预测 |
| IT 风险 | 一般控制/数据验证 | 系统日志 |
| 复核风险 | EQCR/项目复核 | 复核记录 |
| 报告风险 | 沟通/意见/披露 | 报告底稿 |

## 45.6 本章小结

```text
一般审计防“流程和证据”出错；
结构审计防“假设和结构”出错。

一个保“做得全”，
一个保“看得准”。
```

> 审计风险不能降到零，
> 但可以把“没想到”变成“查过了”。
